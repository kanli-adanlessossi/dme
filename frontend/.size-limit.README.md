# Budget de bundle (`size-limit`) — #13 / NFR-11

Garde-fou **bloquant** et **déterministe** de la taille des artefacts de build
(ADR-2 de `.kiro/specs/dev-and-ci-tooling/design.md`). Mesure la taille **gzip**
des fichiers émis par `vite build` (plugin `@size-limit/file` : aucune
re-compilation, aucune variance). Un dépassement renvoie un code non nul et fait
échouer le job CI frontend (étape « Check bundle size budget » de
`.github/workflows/ci.yml`).

## Exécution

```bash
npm run build   # produit dist/ (les seuils portent sur dist/assets/*)
npm run size    # vérifie les budgets ; code non nul si dépassé
```

## Deux budgets distincts (M2)

MapLibre (`maplibre-gl` 4.7.1) était importé **statiquement** dans `TogoMap.tsx`
et `CenterPinPicker.tsx` : il pesait donc dans le bundle d'entrée et se mélangeait
à l'app shell. Il est désormais **code-splitté** (import dynamique `import(...)`
de la librairie + de sa CSS dans l'effet d'initialisation de chaque composant) :
Vite l'émet dans un chunk séparé `assets/maplibre-gl-*`, chargé **à la demande**
quand la carte s'affiche. Les deux concerns sont ainsi mesurés séparément.

| Budget | Fichiers (`dist/assets/`) | Rôle | Limite gzip |
|---|---|---|---|
| **app shell** | `index-*.js` + `index-*.css` | JS/CSS du premier rendu, **hors carte** — métrique la plus liée à NFR-11 « premier affichage » | **217 kB** |
| **chunk carte** | `maplibre-gl-*.js` + `maplibre-gl-*.css` | MapLibre, chargé à la demande | **250 kB** |

Les globs tolèrent le hash Vite (le nom change à chaque build).

## Calibration (état actuel + marge ~10 %)

Mesuré sur la build de l'état actuel (`npm run build` puis `npm run size`) :

| Budget | Taille gzip actuelle | Seuil (+~10 %) |
|---|---|---|
| app shell (`index-*.js` + `index-*.css`) | ~197,0 kB | **217 kB** |
| chunk carte (`maplibre-gl-*.js` + `maplibre-gl-*.css`) | ~226,4 kB | **250 kB** |

La marge laisse respirer les variations normales tout en bloquant une vraie
dérive. **Si la taille réelle évolue légitimement** (nouvelle dépendance
assumée), recalibrer : relancer `npm run size`, relever le seuil au-dessus de la
nouvelle taille + marge, et mettre à jour ce tableau.

## Pourquoi bloquant (et pas Lighthouse)

La taille de bundle est un proxy **stable et sans variance** de la perf de
chargement : parfait garde-fou bloquant. Lighthouse (tâche 6) mesure la vraie
métrique mais varie selon la machine CI → il reste **informatif**, jamais
bloquant (ADR-2).
